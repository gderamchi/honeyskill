# Security v1 primary-source ledger

Checked 2026-10-11. This ledger separates implemented mechanisms, design references and evaluation cautions. It adds no HoneySkill detection result and does not change the code frozen for the current runs.

| Primary source | Relevant contribution | Relationship to this implementation and claim boundary |
| --- | --- | --- |
| [Progent paper, v2](https://arxiv.org/html/2504.11703v2), [pinned checker source](https://github.com/sunblaze-ucb/progent/blob/5be7b63fa96f70bc19b72fbcee81f1c0bcc1a565/secagent/tool.py) | Programmable restrictions on tool arguments, priorities and default denial before execution. | **Implemented subset.** HoneySkill ports static JSON Schema policies with fallback 0 and checks parity against pinned Python definitions. Stateful financial budgets are additional HoneySkill checks. Dynamic updates, fallback agents and the paper's benchmark are outside this replication. See [parity scope](security-v1-progent.md). |
| [CaMeL paper, v2](https://arxiv.org/html/2503.18813v2), [official research code](https://github.com/google-research/camel-prompt-injection) | Separate trusted planning/control flow from untrusted data; constrain permitted information flows through capabilities. | **Design reference.** HoneySkill's trusted financial contract and complete mediation of its exposed action tool use related principles. HoneySkill does not implement the CaMeL interpreter, its full provenance mechanism or its formal claims. Correct policies, complete mediation and implementation assumptions still matter. |
| [FIDES paper, v1](https://arxiv.org/html/2505.23643v1), [Microsoft tutorial](https://github.com/microsoft/fides) | Track confidentiality and integrity labels; hide untrusted values behind references; use isolated model queries and bounded output types to preserve useful planning under policy constraints. | **Extension candidate.** Useful when HoneySkill expands from exact financial actions to reading and transmitting documents. The paper's explicit-secrecy model excludes implicit flows and timing/packet-length side channels. HoneySkill currently has neither FIDES label propagation nor its selective variable store. |
| [AgentDojo paper, NeurIPS 2024](https://arxiv.org/abs/2406.13352), [official project](https://agentdojo.spylab.ai/) | Extensible stateful environments with legitimate task utility and attacker-success checks, including adaptive attacks. | **Evaluation reference.** Evaluate utility and prohibited effects separately against trusted environment state. HoneySkill's package classifiers, synthetic policy regressions and local-chain observations remain different measurement units. No AgentDojo score is imported as HoneySkill evidence. |
| [Cisco Skill Scanner 2.2.2](https://github.com/cisco-ai-defense/skill-scanner/releases/tag/2.2.2), [upstream measured results](https://github.com/cisco-ai-defense/skill-scanner/blob/2.2.2/docs/reference/measured-results.md) | A reusable scanner with static, code/dataflow and optional model analyzers; upstream evaluation exposes threshold, model and coverage trade-offs. | **Executed dependency.** HoneySkill requests the pinned static profile plus AST/dataflow analysis and independently validates completion and citations. Upstream measured configurations are not identical to this profile and cannot establish HoneySkill accuracy. See [artifact pinning](security-v1-research.md). |
| [Adaptive Attacks Break Defenses Against Indirect Prompt Injection Attacks on LLM Agents, NAACL Findings 2025](https://aclanthology.org/2025.findings-naacl.395/) | Defense-aware attacks expose weaknesses missed by testing a fixed collection of injections. | **Evaluation requirement.** Use attackers with knowledge of the policy and scanner interface; retain an untouched evaluation split and fixed query budget. Current external packages and authored regressions do not establish adaptive robustness. |
| [The Attacker Moves Second, USENIX Security 2026](https://www.usenix.org/conference/usenixsecurity26/presentation/nasr) | Stronger optimized and human-guided adaptive attacks bypass a broad set of previously evaluated language-model defenses. | **Stronger caution for detector claims.** A good static-corpus score cannot certify injection resistance. This paper evaluates its stated defenses and threat models; its attack rates are not measurements of HoneySkill or of every deterministic reference monitor. |

Microsoft also documents a possible [FIDES integration in Agent Framework ADR-0024](https://github.com/microsoft/agent-framework/blob/main/docs/decisions/0024-prompt-injection-defense.md). At inspection its status field remains **proposed**. That design document and a tutorial are insufficient evidence that a particular installed framework release implements the required guarantees. Any future adoption needs a pinned implementation review, tests of label assignment at untrusted MCP boundaries, and an explicit tool policy.

The newer [Adaptive Evaluation of Out-of-Band Defenses, v1](https://arxiv.org/html/2606.26479v1) adds a limited independent Progent experiment. Its authors explicitly limit their finding to a small open-weight model setting and one handcrafted black-box attack template. It supports further adaptive evaluation; it does not prove general resistance.

For the next evaluation, freeze the implementation, threshold, labels, family split, allowed attacker knowledge and attack budget before running. Report package detection, analysis coverage, legitimate utility and independently observed prohibited effects separately. Source labels remain evidence to adjudicate, rather than labels that the evaluated LLM can rewrite.

Local reproducibility metadata is recorded in the private relative-path artifact `work/security-runs/runtime-provenance.json`: actual runtime versions, installed scanner file verification, dependency-lock hashes and the Progent parity-witness hash. It contains no model score, credential, workstation path or raw process log.
