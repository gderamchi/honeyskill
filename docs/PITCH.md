# HoneySkill — pitch outline

**Product sentence:** An agent may propose a payment; trusted host policy decides whether the supported action can reach the executor.

## 1. The problem

An agent skill or injected instruction can change a recipient, add a hidden charge, request an unapproved allowance or exceed a user's spending mandate. A model's refusal or explanation is not an enforcement boundary.

## 2. The solution

HoneySkill combines package inspection with a separate deterministic financial monitor. Inspection reports native findings, Cisco Skill Scanner results, modular LLM analysis and coverage. At execution, the monitor checks typed proposals against a trusted host-authored policy before dispatch. It protects only actions that use its adapter.

## 3. The controlled demonstration

Four authored payment scenarios supply six fixed action proposals on an owned local Avalanche fork. Direct execution produced three unauthorized effects; the monitor blocked all three and preserved all three exact legitimate payments. The action-policy matrix is TP 3, FN 0, FP 0, TN 3, with 36/36 local receipt and state checks passing. Proposals are scripted, not generated by an LLM.

## 4. Inspection evidence and limits

The separate development inspection run covered 114 cases: 18 TP, 14 FN and 48 incomplete among 80 externally malicious-labelled packages; 7 FP, 12 TN and 1 incomplete among 20 constructed benign controls; 13 complete and 1 incomplete unknown-label cases. This tuned corpus is not an unseen holdout. These figures must not be combined with the six-action mediation matrix.

## 5. What comes next

HoneySkill is a local hackathon prototype. It is not a production wallet integration, universal terminal interceptor, arbitrary-script sandbox or general-purpose transaction firewall. The fixed recipient-substitution replay remains held and does not replan. A normal-AI comparison, independently adjudicated unseen holdout and broader supported-action evaluation remain outstanding.

The demo uses a disposable owned local chain and no public signed transaction. It does not establish regulatory compliance, real-world malware accuracy or comparative cost, speed or accuracy against a normal AI system.
